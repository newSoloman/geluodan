**sudo 权限：** 用户 deku 可以以 任何用户（ALL） 的身份执行 `/opt/NewComponent/feedback.sh`，无需密码（sudo -l 显示）。

**脚本行为：**

- 提示用户输入反馈内容（`read feedback`）。
- 对输入进行 **黑名单过滤**：禁止包含 `` ` ``、`)`、`$(`、`|`、`&`、`;`、`?`、`!`、`\` 这些字符。
- 如果通过过滤，则执行 `eval "echo $feedback"`（将用户输入作为变量展开并输出），然后将输入追加到 `/var/log/feedback.txt`。
- 如果包含黑名单字符，则报错退出。

**潜在风险：**

`eval "echo $feedback"` 存在 **命令注入** 漏洞。虽然过滤了部分危险字符，但仍可能通过 换行符、空格、引号、通配符 或 环境变量（如 `$PATH`）等方式绕过，从而以 root 权限执行任意命令。

例如，输入 `$(id)` 被禁止，但可以尝试 `$0`、`$SHELL` 或利用 echo 的选项（如 `-e` 转义）进行注入。

**文件权限：**

`/opt/NewComponent/feedback.sh` 所有者为 deku，权限 `-r-xr-xr-x`（其他用户可读可执行但不可写），这意味着 deku 可以修改脚本内容（但当前无需修改，因为 sudo 权限即可）。

**提权思路：** 利用 sudo 运行该脚本，通过精心构造的输入绕过过滤，触发 eval 执行恶意命令（如反弹 shell 或添加 sudo 用户），从而获取 root 权限。

```bash
deku@ip-10-48-159-70:~$ echo -e '#!/bin/bash\nchmod +s /bin/bash' > /opt/NewComponent/feedback.sh
-bash: /opt/NewComponent/feedback.sh: Operation not permitted
```

遇到的 "Operation not permitted" 比普通的 "Permission denied" 更"硬核"：

- **Permission denied：** 通常是 Unix 权限不足（比如文件没有写权限，或你不是 owner），属于常规文件系统权限错误，很容易通过 chmod 或 sudo 解决。
- **Operation not permitted：** 这是内核返回的 EPERM 错误，表示操作被 **系统级机制** 直接禁止，可能的原因包括：
  - 文件被设置了 **不可变属性**（`chattr +i`），即使 root 也不能直接修改（除非先解除）。
  - 文件所在挂载点是 **只读**（如 ISO、ro 挂载）。
  - SELinux / AppArmor 策略拦截了进程对该文件的写操作。
  - 文件系统（如 overlayfs）限制。

在你这种情况下，脚本权限是 `-r-xr-xr-x`（无写位），普通用户自然无法写入，但通常报错是 Permission denied，这里出现 Operation not permitted，极大概率是文件被 `chattr +i` 锁定了（或者存在更底层的保护），以此防止篡改。

## 四、总结

本次靶机渗透路径清晰：

`Web 信息泄漏 → 后门发现 → 反弹 Shell → 隐写提取 SSH 凭据 → 用户 Flag → Sudo 注入提权 → Root Flag`。

关键技巧包括：

- 目录扫描结合文件头判断；
- 利用 steghide 提取隐写数据；
- 绕过黑名单的命令注入利用 `>>` 重定向写入 `/etc/passwd`。
