# Windows 和 AD 基础知识

本篇是 TryHackMe Cyber Security 101 学习路径的第二篇笔记，覆盖 **Windows Fundamentals（Windows 基础）** 与 **Active Directory Basics（活动目录基础）** 两个主题。Windows 是个人电脑和企业办公环境的操作系统霸主，而 Windows 世界里企业网络的"大脑"是 AD——这两块地基打好，后面的域渗透学习才走得动。

## 一、Windows 的版本（Editions）

Windows 不只有"一个 Windows"，微软把系统分成多个**版本（Editions）**，面向不同人群：

| 版本 | 面向人群 | 特点 |
|------|----------|------|
| Windows Home（家庭版） | 普通家庭用户 | 基础功能，安全特性最少，不适合企业 |
| Windows Pro（专业版） | 个人与小型企业 | 增加 BitLocker、远程桌面、**加入域**等企业功能 |
| Windows Enterprise（企业版） | 大型企业 | 在 Pro 基础上增加 DirectAccess、AppLocker 等高级功能 |
| Windows Education（教育版） | 学校等教育机构 | 功能基本等同企业版，专门面向教育 |

对安全从业者来说值得记住：**越是面向个人的版本，内置安全与集中管理功能越少**；企业网络里几乎清一色是 Pro/Enterprise。

## 二、文件系统：NTFS

Windows 默认的现代文件系统是 **NTFS（New Technology File System，新技术文件系统）**。相比古老的 FAT32，NTFS 带来几个关键能力：

- **权限（Permissions）**：精细控制"谁能读、谁能写"某个文件/文件夹
- **加密（Encryption）**：支持 EFS、BitLocker 等加密
- **磁盘配额（Disk Quotas）**：限制用户能占用的磁盘空间
- **备用数据流（ADS，Alternate Data Streams）**：允许一个文件附带隐藏的附加数据（*a feature that allows a file to have additional hidden data attached to it*），也常被攻击者用来藏东西

> 注：ADS 是经典的后渗透"藏文件"手法——把恶意内容藏进正常文件的附加流里，用资源管理器或普通的 `dir` 是看不到的。

## 三、System32 文件夹

`C:\Windows\System32` 是 Windows 的核心系统目录，存放支撑系统运行的关键程序与动态链接库（DLL）。它**是整个操作系统的灵魂**：攻击者一旦能向其中写入 DLL 或拿到 System32 的写入权限，往往意味着系统已被完全控制。日常使用中**不要**随意删除、修改这个目录里的文件。

## 四、用户账户与 UAC

Windows 有两种主要账户类型：

- **管理员（Administrator）**：拥有对电脑的全部控制权，可以装软件、改系统设置、删任何文件
- **标准用户（Standard User）**：日常使用账户，权限受限，避免误操作或恶意软件改动系统

微软的安全设计默认开启了 **UAC（User Account Control，用户账户控制）**：即使你是管理员，执行需要高权限的操作时也会弹出"是否允许"的确认框（*UAC prompts for confirmation before a program makes changes that require admin privileges*）。这个弹窗是防恶意软件的重要防线——正规软件不会滥用高权限，恶意软件则很难静默绕过。

## 五、控制面板与设置

Windows 有两个改设置的地方，容易让人困惑：

- **控制面板（Control Panel）**：老式设置界面，Windows 7 时代的遗产，管理"程序和功能"（卸载软件）、系统、网络等
- **设置（Settings）**：Windows 8 之后的新式界面，越来越多的设置只在这里出现

两者功能有重叠，新系统的设置正在逐渐取代控制面板。

## 六、任务管理器（Task Manager）

按 `Ctrl + Shift + Esc` 打开。它是排查性能问题、发现可疑进程的第一现场：

- **进程（Processes）**：正在运行的程序及其 CPU/内存/磁盘占用
- **性能（Performance）**：CPU、内存、磁盘、网络的实时图表
- **启动（Startup）**：开机自启动的程序（也是恶意软件最爱常驻的位置）
- **服务（Services）**：系统服务列表

## 七、系统工具全家桶

Windows 自带一批系统管理工具，网络安全学习经常用到：

| 工具 | 用途 |
|------|------|
| 系统配置（msconfig） | 配置开机启动项、系统服务、引导选项 |
| 计算机管理（Computer Management） | 集中管理事件日志、用户与组、设备管理器等 |
| 系统信息（System Information / msinfo32） | 查看硬件与系统环境的详细信息 |
| 资源监视器（Resource Monitor） | 比任务管理器更详细的资源占用分析 |
| 注册表编辑器（regedit） | 查看/修改 Windows 注册表——系统配置的"数据库" |
| 组策略编辑器（gpedit.msc） | 编辑本地组策略（企业环境通常由 AD 下发的组策略接管） |
| 事件查看器（Event Viewer） | 查看系统、安全、应用程序日志 |

**Windows 安全中心（Windows Security）** 则是 Defender 杀毒、防火墙、BitLocker 加密、应用与浏览器控制等安全功能的统一入口。

> 注：事件查看器里的**安全日志（Security Log）**记录登录成功/失败等事件，是蓝队排查入侵痕迹、红队隐匿操作都必须关注的战场。

## 八、为什么要引入"域"

单台电脑的账户、密码、策略都各自管理，几百台电脑就是几百个"孤岛"。企业需要一种**集中管理**的方式，于是有了 Windows 域。

**域（Domain）** 是一组由同一个**域控制器（DC，Domain Controller）** 统一管理的电脑和账户组成的网络（*a group of users and computers that are all under the control of a single authority*）。域里的用户在**任意一台**加入域的电脑上都能用**同一套账户密码**登录——账户和密码只保存在域控制器上，电脑本身不存。

## 九、Active Directory 与域控制器

**活动目录（Active Directory，AD）**：微软的目录服务，存放网络里所有"对象"（用户、电脑、打印机、组等）的数据库（*a directory service that stores information about objects on the network*）。**域控制器（DC）** 就是运行 AD 的那台服务器，是 Windows 域网络的**心脏**。

AD 的层级组织（**AD DS，Active Directory Domain Services**）：

- **域（Domain）**：AD 的基本单元，如 `tryhackme.com`
- **树（Tree）**：多个共享同一个命名空间根的域连在一起，如 `tryhackme.com` 与它的子域 `research.tryhackme.com`
- **林（Forest）**：一棵或多棵树的集合，是整个 AD 的边界（也是信任关系的边界）

## 十、用户与组

**用户（Users）**：AD 里为每个员工创建的账户对象，分普通用户、管理员等。AD 内置了 `Administrator`（域管理员）、`Guest`（访客）等特殊账户。

**组（Groups）**：把一堆用户打包管理，给组授权就相当于给组内所有人授权。AD 里典型的组有：

| 组 | 作用 |
|----|------|
| Domain Admins（域管理员） | 对整个域有完全控制权，**最危险**的账户 |
| Domain Users（域用户） | 普通域用户，所有新建的域用户默认加入 |
| Enterprise Admins（企业管理员） | 对整个林有完全控制权 |
| Local Administrators（本地管理员） | 对**本机**有完全控制权（每台电脑各自维护） |

> 注：拿到 `Domain Admins` 或 `Enterprise Admins` 权限 ≈ 拿下整个域/林。这就是为什么攻击者拿到一台普通域内主机后，总会努力做**权限提升**去拿域管理权限。

**组织单位（OU，Organisational Unit）** 则用来按部门/职能把对象分组管理（如 `Sales`、`IT`），可用来定向下发组策略。

## 十一、信任与策略

- **信任关系（Trust Relationships）**：让不同域/林之间的用户可以互相访问资源。信任可以单向也可以双向——**A 信任 B 不代表 B 信任 A**（*trust direction matters*）。攻击者有时会利用信任关系作为横向移动的跳板。
- **组策略（Group Policy，GPO）**：域控制器上集中定义的配置策略（密码策略、软件安装、脚本、安全设置等），通过 **SYSVOL** 共享文件夹下发到域内所有电脑（*GPOs are enforced by the DC across the network*）。客户端每次登录或刷新时会拉取生效。

## 十二、AD 中的身份验证：Kerberos 与 NetNTLM

域环境里用户登录时，身份验证由域控制器完成，主要走两种协议：

- **Kerberos**：默认协议。用户先在 KDC（域控制器上运行）那里换取**票据（Tickets）**，再拿票据去访问各种服务，整个过程**不传密码本身**，而是用加密的票据证明身份（*uses tickets to prove identity without sending the password*）。票据有有效期，到期需重新申请。
- **NetNTLM（NTLM 认证）**：旧协议、兼容协议。客户端通过一个**挑战-响应（Challenge-Response）**过程向服务器证明自己知道密码（*a challenge-response protocol that proves knowledge of the password*），服务器再把问题转发给 DC 验证。

> 注：攻击面视角——Kerberos 有 Kerberoasting、票据伪造（Golden/Silver Ticket）等著名攻击；NetNTLM 的哈希可以被中继（Relay）或离线破解。这些是后续渗透测试阶段的内容。
