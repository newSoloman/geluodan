# SQL注入介绍

## 1. SQL注入基础

### 一、SQL 注释符（Comment）

**作用：** 用于闭合引号后，注释掉原始 SQL 语句中多余的代码，使注入生效。

**常见注释符号：**

1. **`--`（双连字符）**
   注意：`--` 后面必须跟一个空格（或制表符/换行）才能生效。
   示例：`admin' --`
   原句：`SELECT * FROM users WHERE username='admin' -- ' AND password='secret';`
   结果：密码验证被注释掉。

2. **`#`（井号）**
   注：在 URL 编码中通常写成 `%23`。
   示例：`admin'#`
   结果：与 `--` 作用相同，注释掉后面的内容。

3. **`/* */`（多行注释）**
   作用：注释掉中间的 SQL 语句。常用于绕过某些过滤，或进行时间盲注（如休眠）。
   示例：`admin'/*!*/ -- `
   （注：`/*! ... */` 在 MySQL 中还可用于执行特定版本的 SQL 代码，称为 Hints）

### 二、UNION 注入（联合查询注入）

**作用：** 当两个查询的列数相同时，可以将两个结果集合并。利用这一点，可以在原有查询结果后面显示我们想要的数据（如数据库名、表名、密码）。

**核心前置步骤：**

1. 确定列数（使用 ORDER BY 或 UNION SELECT NULL）：
   ```sql
   ' ORDER BY 1 -- 
   ' ORDER BY 2 -- 
   ```
   ... 直到报错，确定列数 N。

2. 查出显示位（确定哪几列的数据会回显到页面上）：
   ```sql
   ' UNION SELECT 1,2,3,...,N -- 
   ```

3. 利用显示位获取数据（例如显示位为 2 和 3）：
   ```sql
   ' UNION SELECT 1,database(),user() -- 
   ```

**注：** UNION 默认去重，如果第一句查询为空，或者使用 UNION ALL 可以更稳定地显示所有结果。

### 三、LIKE 与 通配符（Wildcards）

**作用：** 在 SQL 注入中，常用于盲注（Boolean-based Blind SQL Injection），通过逐字猜解数据。

**通配符：**

1. **`%`（百分号）：** 代表零个、一个或多个任意字符。
   示例：`SELECT * FROM users WHERE username LIKE 'a%';`（查找以 a 开头的用户名）
   注入利用：常用于判断表名是否存在，如：
   ```sql
   ' OR username LIKE 'admin%' -- （判断是否存在 admin 开头的用户）
   ```

2. **`_`（下划线）：** 代表单一的任意字符。
   示例：`SELECT * FROM users WHERE username LIKE 'ad_in';`（匹配 admin 或 adxin）
   注入利用：用于精确猜解某个位置的字符，如：
   ```sql
   ' OR username LIKE 'admi_' -- （判断是否有长度正好为5且前4位是admi的用户）
   ```

**注意：** 在盲注中，结合 SUBSTRING 和 ASCII 码使用更精准，但 LIKE 的 `_` 常用于快速爆破固定长度字符串。

### 四、LIMIT 子句

**作用：** 限制查询返回的行数。在注入中，常用于分页显示，或者当 UNION 只能返回一行数据时，用来遍历数据表中的多条记录。

**基础语法：**

```sql
LIMIT offset, count  （偏移量, 返回行数）
或 LIMIT count OFFSET offset
```

**注入利用示例（遍历表名）：**

假设表名存储在 information_schema.tables 中：

```sql
' UNION SELECT table_name, 2, 3 FROM information_schema.tables LIMIT 0, 1 -- 
```
（返回第一条表名）

```sql
' UNION SELECT table_name, 2, 3 FROM information_schema.tables LIMIT 1, 1 -- 
```
（返回第二条表名）

**注：** 在 MySQL 中，如果 LIMIT 后面跟注入语句，有时可以配合 PROCEDURE ANALYSE() 进行报错注入。

### 五、字符串函数（String Functions）

**作用：** 在注入过程中，用于处理、截取、比较或编码字符串数据，是盲注和报错注入的核心工具。

**常用函数列表：**

1. **获取信息类：**
   - `database()`：返回当前数据库名。
   - `user()` / `system_user()`：返回当前连接数据库的用户名。
   - `version()`：返回数据库版本号（对判断注入类型很重要）。

2. **截取/获取长度类（盲注必备）：**
   - `length(str)`：返回字符串的长度。
   - `substr(str, pos, len)` / `substring()`：截取字符串（从位置 pos 开始，取 len 个字符）。
   - `mid(str, pos, len)`：同 substring。
   - `left(str, len)`：返回字符串左边的 len 个字符。
   - `right(str, len)`：返回字符串右边的 len 个字符。

3. **比较与转换类（绕过过滤）：**
   - `ascii(str)`：返回字符串第一个字符的 ASCII 码值（盲注最常用，配合大于小于号判断）。
   - `ord()`：同 ascii。
   - `hex(str)`：将字符串转为十六进制（可用于绕过引号限制）。
   - `unhex(hex_str)`：将十六进制转回字符串。
   - `char(ascii_code)`：将 ASCII 码转为字符。

4. **拼接类（多行结果显示）：**
   - `concat(str1, str2)`：拼接多个字符串。
   - `concat_ws(sep, str1, str2)`：以分隔符 sep 拼接字符串（如 `concat_ws(':', user, password)`）。

5. **编码绕过类：**
   - `md5(str)`：返回 MD5 哈希值（有时用于绕过某些 WAF）。
   - `hex()` / `unhex()`：如上述，用于绕过引号（例如：`SELECT * FROM users WHERE username = 0x61646D696E`；0x61646D696E 是 'admin' 的十六进制）。

## 2. 什么是SQL注入以及三种类型

### 一、什么是SQL注入（SQL Injection）

SQL注入是指攻击者通过操纵Web应用程序的输入参数（如URL中的ID、表单输入框、Cookie等），将精心构造的恶意SQL代码“注入”到后台数据库查询语句中，从而改变原始SQL语句的逻辑结构。

最终结果：攻击者可以绕过身份验证、窃取敏感数据（如密码、邮箱）、篡改数据，甚至获取数据库服务器的控制权限（提权、执行系统命令）。

**【核心成因】**

程序在拼接SQL语句时，未对用户输入的数据进行严格的过滤或参数化处理，导致用户输入的内容被数据库服务器当作SQL代码来执行。

### 二、SQL注入的三种主要类型（按数据传递与响应方式分类）

在实际攻防场景中，根据“数据如何交互”以及“结果如何回显”，SQL注入通常分为以下三大类：

#### 类型一：经典注入 / 回显注入（In-band SQLi）

这是最直接、最容易利用的一种注入方式。攻击者使用相同的通信通道（即网页本身）发起攻击并接收查询结果。

**特点：** 数据直接在页面上可见。细分为两种常见子类型：

1. **联合查询注入（UNION-based SQLi）：**
   利用 UNION 或 UNION ALL 关键字，将攻击者想要的查询结果（如密码表）拼接到原始查询结果后面，并显示在页面上。
   例：`' UNION SELECT username, password FROM users --`

2. **报错注入（Error-based SQLi）：**
   利用数据库的报错信息，将查询到的数据直接通过错误提示带出来。
   例：利用 updatexml() 或 convert() 函数触发类型转换错误，使数据库在报错信息中返回目标数据。

**判断特征：** 页面有具体数据显示变化，或有明确的数据库报错回显。

#### 类型二：布尔盲注（Boolean-based Blind SQLi）

当页面没有报错信息，也不显示具体数据时，但页面会根据SQL查询条件的“真”或“假”返回截然不同的两种页面状态（例如：显示“欢迎回来” vs “用户名不存在”）。

**原理：** 攻击者通过构造永真条件（and 1=1）和永假条件（and 1=2），观察页面的细微差异，逐字逐位地“猜”出数据库中的数据。

**常用函数：** `ascii()`、`substr()`、`length()`

**经典判断：** `' AND SUBSTRING((SELECT database()),1,1) = 'a' -- `

**判断特征：** 页面没有数据回显，只有“正常显示”与“空白/报错/跳转”两种状态变化。

**利用成本：** 耗时较长，需大量发包进行爆破。

#### 类型三：时间盲注（Time-based Blind SQLi）

当页面既没有数据回显，也没有布尔的真假状态变化（即无论输入什么都显示相同页面），但数据库能够执行延时函数时，可以利用时间延迟来判断条件是否成立。

**原理：** 构造条件语句，如果条件为真，则执行 sleep()（或 waitfor delay）等延时函数；如果为假，则立即返回。攻击者通过监测服务器响应的毫秒/秒级时间差异来提取数据。

**常用函数：**

- MySQL: `sleep(5)`
- SQL Server: `waitfor delay '0:0:5'`
- PostgreSQL: `pg_sleep(5)`

**示例判断：** `' AND IF(ASCII(SUBSTR((SELECT database()),1,1))=97, SLEEP(5), 0) --`

**判断特征：** 无论输入什么，页面内容完全一样。只能通过浏览器“加载耗时”的长短来推断。

**利用成本：** 最耗费时间，通常需要写自动化脚本（如Python）来逐字符注入。
